## How access works

SchoolDB uses three access layers:

1. **School access** — a Super Admin can decide which modules are enabled for a school.
2. **Role access** — each role starts with a safe set of relevant modules.
3. **Individual staff access** — an administrator can give a Teacher, Accountant, or Receptionist custom `View`, `Manage`, or `No access` permission for each module.

The menus shown to a user are the result of all three layers. A user may therefore see fewer options than the examples in these guides. Access is also checked by the server; hiding a menu is not the security control.

## Role summary

| Role | Main responsibility | Default workspace |
|---|---|---|
| Super Admin | Schools, route access, administrators, and full operations | Admin workspace |
| Principal / School Admin | Daily school leadership and full school operations | Admin workspace |
| Teacher | Assigned students, attendance, homework, exams, and timetable | Teacher dashboard |
| Accountant | Fees, receipts, expenses, payroll, and inventory | Operations dashboard |
| Receptionist | Admissions, students, IDs, visitors, health, pickup, and maintenance | Operations dashboard |
| Parent | Monitor and act for linked children | Student space |
| Student | View personal academic and school information | Student space |

> Keep each login personal. Never share OTPs, passkeys, exported student data, or printed documents with an unauthorized person.
