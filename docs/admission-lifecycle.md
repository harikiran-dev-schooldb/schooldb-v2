# Admission lifecycle
The staff enquiry conversion creates and links a submitted application atomically, requires genuine DOB/gender, checks age policy and same-school/year duplicates, and does not assume messaging consent. Document review is optional by default, admin-controlled, and enforced on approval/conversion when required. It verifies existing uploads, not a statutory checklist. Fee assignment is optional and administrator-confirmed at conversion; same-year, school, class and installment validation applies. The enrollment, student, fee assignment and unpaid installment snapshot are in one transaction, including verified RTE waiver selection; no money is collected. Existing login provisioning and consent-based WhatsApp status flow remain in place. Admin reminders are opt-in and reuse the existing daily push cron; a generic summary excludes student personal information. CSV export is administrator-only and year-scoped. Actual payment-before-enrollment, mandatory document types, standalone deleted-record migration, per-staff exact-time push, branded offer letters, and full authenticated testing remain pending. Before historical import, verify school approval, data minimization, schema mapping, duplicate handling, backup and rollback. No production data was imported or messages sent by implementing this code.
